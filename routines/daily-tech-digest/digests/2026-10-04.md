# Digest envoyé — 2026-10-04

## Message

🗞 Veille — dimanche 4 octobre

🤖 IA / Agents
• Les agents n'ont pas besoin de mémoire, ils ont besoin de documentation — Plutôt qu'un vector store RAG façon "loterie de snippets", l'auteur propose un cycle consulter → construire → mettre à jour des fichiers Markdown que l'agent lit et édite lui-même. Débat animé sur HN : moins de mémoire opaque, plus de documentation versionnée et partageable en équipe.
• Il va falloir des plafonds de dépense durs, par défaut, sur (presque) tout — Simon Willison plaide pour des plafonds qui coupent réellement le service plutôt qu'un simple email d'alerte, après des utilisateurs réveillés avec des factures à plusieurs milliers de dollars causées par des agents devenus incontrôlables pendant la nuit. Pour qui branche des agents sur des APIs payantes en boucle : un circuit-breaker de coût vaut mieux qu'un monitoring passif.
• RouteFM : un routeur de LLM entraîné une fois, réutilisable sur n'importe quel pool de modèles — Les routeurs qui dispatchent vers le modèle le plus adapté doivent aujourd'hui être ré-entraînés à chaque changement de pool ; ce papier propose un routeur en contexte qui s'adapte à un nouveau pool à partir de quelques observations, sans ré-entraînement. Pour une passerelle multi-modèles en prod, ça évite de reconstruire le routeur à chaque ajout ou retrait de fournisseur.

🏗 Archi
• Dompter les API asynchrones à grande échelle — Ian Cooper propose un cadre "ABC" (Address/Binding/Contract) : discovery via specs AsyncAPI/CloudEvents, gouvernance par schema registry avec gates CI/CD, provisioning généré depuis la spec (topics Kafka, IAM, ACL). De quoi éviter l'estate de messaging ingérable passé 5-6 équipes, où le wiki est la seule doc et les breaking changes explosent en prod.
• La plateforme GenAI interne de DoorDash, deux ans après — Un LLM Gateway qui abstrait les providers (coût, observabilité, fallback), puis un pivot vers des modèles open-weights self-hébergés pour diviser les coûts par 20 et sortir de la dépendance vendor ; l'infra s'étend ensuite en Agent Gateway pour gérer MCP, auth et rate-limiting sur 50+ outils. Un pattern gateway + abstraction stable qui évite de réécrire les intégrations à chaque changement de fournisseur.

🧱 System design
• Uber Eats réduit de 50% la latence de sa recherche — Pas de réécriture architecturale : changement de métrique (ce que l'utilisateur perçoit plutôt que le temps de réponse API), suppression des lookups et embeddings à faible valeur, découplage ranking/présentation avec request hedging, données publicitaires en colonnes en mémoire. Une méthode reproductible — mesurer puis traquer les dépendances superflues couche par couche.

🛠 Dev
• Zig 0.17.0 : build system refait, compilation incrémentale quasi instantanée — Le linker ELF est réécrit pour une compilation incrémentale quasi instantanée sur x86_64-linux (-fincremental --watch), la config de build passe en binaire (-25% de taille), et un nouveau Build Server Protocol améliore l'intégration IDE/LSP. Contrepartie : plusieurs breaking changes, dont un changement silencieux de sémantique sur @bitCast, qui imposent une migration non triviale.
