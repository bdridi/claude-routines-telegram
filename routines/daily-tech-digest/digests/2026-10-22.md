# Digest envoyé — 2026-10-22

## Message

🗞 Veille — jeudi 22 octobre

🤖 IA / Agents
• LiteLLM piraté sur PyPI : voleur d'identifiants et porte dérobée dans la release 1.107.0
  L'attaquant a utilisé des identifiants GitHub de développeurs fuités depuis les logs d'un déploiement interne exposé, contourné la protection de branche, et fait publier des wheels/images Docker vérolés par le pipeline officiel lui-même. Le malware collectait clés SSH, secrets cloud/CI et clés de fournisseurs LLM stockées dans le proxy — la leçon : vérifier les artefacts par hash, pas seulement la version, et traiter tout hôte ayant installé la release comme compromis.
• Cache Engineering : piloter le KV-cache d'un agent plutôt que réécrire son historique
  Au lieu de résumer ou tronquer l'historique texte — ce qui invalide le cache et force un re-calcul — l'agent manipule directement son cache de clés/valeurs actif via trois opérations (ajouter, exclure, repositionner). Résultat sur SWE-bench Verified : -27,7% de coût, +1,18x de débit et un p95 1,51x plus rapide qu'avec un résumé classique, pour une précision légèrement meilleure.
• Demander un score de confiance à un LLM ne mesure rien
  Le chiffre est du texte généré token par token, jamais entraîné à refléter un taux de réussite réel : reposer la même question, ou juste ajouter "tu es sûr ?", change le score sans nouvelle information. L'alternative proposée : calculer la confiance en dehors du modèle, à partir de signaux observables calibrés sur des résultats loggés, pas en la demandant au LLM.

🏗 Archi
• WebMCP : l'agent d'achat appelle un outil plutôt que de cliquer sur du HTML
  Standard expérimental où le site expose des outils structurés (ex. search_products) via document.modelContext, injectés par Cloudflare en edge sans code côté marchand. Commerce.com l'active sur presque 100 000 domaines avec un opt-out par marchand — un vrai changement de patron d'interaction agent/site, même si le billet reste aussi une annonce partenaire.
• Netflix fait se répondre deux identités : rôle IAM AWS et PKI interne
  Un job Spark prouve que son rôle IAM AWS correspond à son identité interne (Metatron) via une preuve STS signée par le driver, comparée aux métadonnées émises par le control plane — un patron transposable partout où une identité cloud doit prouver une appartenance organisationnelle séparée.

🧱 System design
• GitHub resserre le quorum d'écriture Git à la référence, pas au dépôt entier
  Un verrou à l'échelle du dépôt forçait toute écriture à attendre la réplique la plus lente (~25ms) même sur une branche différente. Le nouveau quorum par référence débloque les écritures indépendantes, et une réplique d'écriture éphémère fait le pont vers Azure Blob Storage en n'accusant réception qu'une fois les données durables. Gain mesuré : 3 à 4x de débit en plus à latence réduite.
• Faire tourner du Spring Batch distribué sans broker de messages
  Plutôt qu'ajouter Kafka ou RabbitMQ juste pour répartir des partitions entre nœuds, cette approche utilise la base relationnelle que Spring Batch exige déjà comme couche de coordination — trois tables, mastership décentralisée par exécution, reprise sur heartbeat. Tient bien de 2 à 20 nœuds ; au-delà, ou sous la seconde de latence de coordination, un broker reste nécessaire.
