# Digest envoyé — 2026-09-21

## Message

🗞 Veille — lundi 21 septembre

🤖 IA / Agents
• AX, l'orchestrateur d'agents en volume de Google — Google publie AX, un orchestrateur déclaratif façon kubectl pour faire tourner des milliards de tâches d'agents autonomes : sandboxing CPU/mémoire, dépôts Git et serveurs MCP précâblés, trafic sortant restreint par liste d'hôtes. Pensé pour la nouvelle classe de charge de travail que sont les agents à état, là où les orchestrateurs existants ciblent des microservices sans état.
• CodeMidas : transformer n'importe quel dépôt en terrain d'entraînement RL — Un pipeline d'agents génère automatiquement tests et spécifications comportementales à partir de code open-source existant, sans autre intrant que le code lui-même. 5 545 tâches issues de 3 185 dépôts et 23 langages : +11,7% sur la réparation de bugs, +17% sur la construction de programmes entiers après entraînement RL dessus.

🏗 Archi
• LinkedIn construit une couche de contexte organisationnel pour ses agents — Plutôt que de laisser chaque agent redécouvrir le contexte d'une base de code gigantesque, LinkedIn expose une couche de contexte partagée via le Model Context Protocol : conventions d'équipe, historique de décisions, propriété du code. Le contexte devient une infrastructure à part entière, pas un prompt à reconstruire à chaque session.

📡 Radar — ThoughtWorks Technology Radar Vol 34
• Structured output from LLMs — Adopt
  Contraindre les LLM à répondre dans un format prédéfini (JSON, classe typée) plutôt qu'en texte libre. Devenu un choix par défaut sensé en production pour tout ce qui consomme la réponse par programme ; le radar recommande une couche d'abstraction (Instructor, Pydantic AI, Outlines) plutôt que l'API brute d'un seul fournisseur.
• Code intelligence as agentic tooling — Assess
  Les agents de code actuels reconstruisent par recherche textuelle une information qui existe déjà dans l'arbre syntaxique — d'où des éditions fragiles et des tokens gaspillés. Le radar recommande de déléguer aux outils déterministes (serveurs LSP, codemods) plutôt qu'à des diffs générés à l'aveugle.
• Measuring collaboration quality with coding agents — Assess
  La plupart des métriques actuelles ne regardent que la vitesse (temps au premier output, lignes générées) plutôt que la qualité réelle. Le radar pousse vers le taux d'acceptation au premier passage, le rework post-fusion et la charge de revue, combinés aux DORA metrics existantes.
